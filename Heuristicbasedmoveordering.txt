Heuristic-based move ordering for alpha-beta
Problem: Before searching each node's children, simulate every move, 
evaluate the resulting state with the existing heuristic, and sort children 
best-to-worst (maximizer) or worst-to-best (minimizer). Count nodes visited 
with and without this ordering, using the same depth and heuristic both times.

def ordered_moves(state, player, heuristic_num, weights, maximizing):
    scored = []
    for m in state.legal_moves(player):
        child = state.copy()
        child.apply_move(player, m)
        val = child.evaluate(PLAYER1, heuristic_num, weights)
        scored.append((val, m))
    # values are always PLAYER1-relative:
    # maximizer wants HIGH values first, minimizer wants LOW values first
    scored.sort(key=lambda x: x[0], reverse=maximizing)
    return [m for _, m in scored]

# inside max_value / min_value, before the search loop:
if use_ordering:
    moves = ordered_moves(state, PLAYER1, heuristic_num, weights, maximizing=True)

A global nodes_visited counter (incremented at the top of every max_value/min_value call) 
is reset and re-run once with use_ordering=False, once with True, to produce the two counts side by side.
Result: at depth 6, ordering cut nodes from 1707 → 1699 — a modest gain, 
since a one-ply heuristic only loosely predicts the true depth-6 value.
